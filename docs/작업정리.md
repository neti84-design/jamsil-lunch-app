## 1. 다른 컴퓨터에서 똑같이 띄우기 (가장 빠른 방법)

코드는 전부 GitHub 에 있으니 **새로 만들 필요 없이 내려받으면 됩니다.** 따로 챙겨야 하는 것은
**비밀값 3가지**(Supabase 주소·키, 관리자 비밀번호)뿐입니다. 이 값들은 저장소에 들어 있지 않습니다.

### 1-1. 준비물

| 항목 | 버전/내용 |
| --- | --- |
| Node.js | 22 이상 권장 (작업 환경은 v22.22) |
| Git | 아무 버전 |
| Supabase 프로젝트 | 기존 프로젝트 그대로 씀 (새로 만들 필요 없음) |
| Vercel 프로젝트 | `jamsim` (이미 GitHub `main` 과 연결돼 있으면 손댈 것 없음) |

### 1-2. 명령어

```bash
git clone https://github.com/neti84-design/jamsil-lunch-app.git
cd jamsil-lunch-app
npm install
cp .env.example .env      # 그리고 아래 값 채우기
npm run dev               # http://localhost:5173
npm run build             # 배포용 빌드 (dist/)
npm run lint              # oxlint 검사
```

### 1-3. `.env` 에 넣을 값

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co      # Supabase > Settings > API > Project URL
VITE_SUPABASE_ANON_KEY=eyJ...                        # Supabase > Settings > API > anon public
VITE_ADMIN_KEY=admin                                 # (선택) Supabase 없이 쓸 때 관리자 비밀번호
```

- 값은 **기존 컴퓨터의 `.env`** 또는 **Vercel > 프로젝트 > Settings > Environment Variables** 에서 복사하면 됩니다.
- `.env` 가 없어도 앱은 뜹니다. 대신 후기·웨이팅이 "이 기기에만 저장"되고 동료와 공유되지 않습니다.
- Supabase 에 연결됐을 때의 관리자 비밀번호는 `.env` 가 아니라 DB 의 `app_config` 표(`admin_token`)에 있습니다.

### 1-4. 카카오 데이터 스크립트를 돌릴 때만 필요한 것

식당 목록을 다시 받을 때만 씁니다. 평소엔 필요 없습니다.

```bash
KAKAO_REST_KEY=발급키 node scripts/kakao-import.mjs 1000                 # 잠실 반경 1km 음식점 → src/data/kakaoPlaces.ts
NODE_USE_ENV_PROXY=1 node scripts/kakao-menu.mjs                         # 메뉴·가격·영업시간·사진 → kakaoDetails.ts, kakaoPhotos.ts
SITE=ydp NODE_USE_ENV_PROXY=1 node scripts/kakao-import.mjs 1000         # 영등포 → src/data/ydp/kakaoPlaces.ts
SITE=ydp NODE_USE_ENV_PROXY=1 node scripts/kakao-menu.mjs                # 영등포 상세
KAKAO_REST_KEY=발급키 node scripts/kakao-enrich.mjs [--apply]            # 직접 정리한 식당 좌표·전화 보정
```

- `KAKAO_REST_KEY`: https://developers.kakao.com 에서 앱 만들고 **REST API 키** 발급.
- `kakao-menu.mjs` 는 카카오맵 가게 페이지(`place-api.map.kakao.com`)를 읽으므로 네트워크에서 그 주소가 열려 있어야 합니다.

### 1-5. Supabase 를 처음부터 새로 만들어야 한다면

1. https://supabase.com → New project (리전: Northeast Asia (Seoul))
2. SQL Editor 에 `supabase/schema.sql` 전체를 붙여넣고 Run (여러 번 돌려도 안전, v1~v9 전부 포함)
3. 실행 전에 파일 안 `'change-me'` 를 원하는 관리자 비밀번호로 바꾸기
   (이미 실행했다면 `update public.app_config set value = '새비밀번호' where key = 'admin_token';`)
4. Settings → API 에서 URL·anon 키를 `.env` 와 Vercel 환경변수에 넣기
5. ⚠️ 새 프로젝트로 바꾸면 **기존 후기·웨이팅·투표·공유톡 데이터는 따라오지 않습니다.** 동료들과 같은 데이터를 보려면 기존 프로젝트 값을 쓰세요.

### 1-6. Vercel 배포

- 이미 연결돼 있으면 `main` 에 푸시할 때마다 자동 배포됩니다. 다른 컴퓨터에서도 `git push` 만 하면 됩니다.
- 새로 연결할 때: Vercel → Add New → Project → `jamsil-lunch-app` Import → 이름 `jamsim` → 환경변수 2개(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) → Deploy.
  빌드 설정은 `vercel.json` 에 들어 있습니다 (Vite, `npm run build`, `dist`, 모든 경로 → `index.html`).

### 1-7. Claude Code 로 이어서 작업할 때

- 새 컴퓨터에서 `claude` 를 저장소 폴더에서 실행하면 됩니다. 이 문서와 `README.md` 를 먼저 읽으라고 하면 맥락을 바로 잡습니다.
- 지금까지 작업 방식: 기능 하나마다 `claude/…` 브랜치 → PR → `main` 머지 → Vercel 자동 배포.

## 4. 기술 스택 · 구조

- **Vite 8 · React 19 · TypeScript 6** · react-leaflet 5 (+ react-leaflet-cluster) · @supabase/supabase-js 2 · oxlint
- 백엔드 서버 없음. 데이터는 ① 코드 안 정적 데이터(식당) + ② Supabase(공유 데이터, Realtime 구독)
- 배포: Vercel (`vercel.json`)

```

  types.ts             Restaurant 타입, 분류 라벨
  components/          HomeView, FilterBar, RestaurantCard, RestaurantDetail, MapView, MapSheet,
                       TodayPick, VotePanel, VoteHome, WhoPicker, ShareTalk, RecentReviews, LiveTicker,
                       ReportPanel(후기·체크), FixPanel(직접 수정), FeedbackPanel, AdminPanel,
                       SiteSwitch, BottomNav, SearchBox, ShareButton, Thumb, HScroll, TowerLogo
  hooks/               useReports, useTalk, useVotes, useTileStatus, useWide
  lib/
```

### Supabase 스키마 요약 (`supabase/schema.sql`)

| 버전 | 내용 |
| --- | --- |
| v1~v2 | `reports` (웨이팅·후기·태그·수정 제보, `device_id`), `app_config`(관리자 비밀번호), `admin_check`·`admin_delete_report`·`delete_own_report` 함수, Realtime |
| v3 | 찜(`fav`)도 태그로 공유 → 동료 추천 |
| v4 | 공유톡 `talk_posts`·`talk_comments`, 관리자 함수, `delivery` 태그 |
| v5 | 점심 투표 `polls`·`poll_votes`, `add_poll_candidate`·`delete_own_poll_vote` |
| v6 | 많이 본 매장 `restaurant_views` (하루 단위 집계), `bump_view` |
| v7 | 누구나 공유톡 올리기 `talk_create`(하루 3개)·`delete_own_talk_post` |

| v9 | Storage `photos` 버킷 (메인 사진 올리기) |

보안 방식: 익명 키로 읽기/쓰기, 삭제·관리 작업은 `security definer` 함수로만(본인 기기 또는 관리자 비밀번호). 링크 아는 사람만 쓰는 사내용 전제.

### 브라우저 저장값 (localStorage, 접두사 `jamsil-lunch:`)
근무지(`site`), 찜(`favorites`, `favorites-private`), 최근 본 식당(`recent`), 최근 검색어(`searches`), 투표 초안(`vote-draft`), 기기 시드(`seed`), 날씨 캐시(`weather2`), 기기 id, 관리자 비밀번호 등.
→ 기기별 값이라 다른 컴퓨터로 옮겨지지 않습니다(찜 목록 등은 새 기기에서 다시).

## 5. 데이터 관리 방법

- **식당 직접 추가**: `src/data/restaurants.ts` 배열에 항목 추가 (형식은 `README.md` "식당 추가하기"). `links.kakaoMap` 을 넣으면 카카오 자동 목록에서 중복 제외.
- **신규 표시**: `src/data/newPlaces.ts` 에 `'식당id': '등록일'` 추가 (카카오 식당 id 는 `kakao-카카오id`).
- **임직원 혜택 매장**: `src/data/partners.ts` 에 `{ site, id, pitch, benefit, until }` 추가 (현재 비어 있음).
- **폐업 삭제**: 해당 식당을 데이터에서 빼거나 제외 목록에 추가 (예: 이태리부대찌개 잠실역점 삭제 커밋 참고).
- **주요장소 추가**: `src/lib/buildings.ts` 의 `BUILDINGS` 에 이름·이모지·주소 정규식 추가.
- 카카오 자료는 공식 API 가 아닌 부분이 있어 카카오가 형식을 바꾸면 스크립트 수정 필요.
